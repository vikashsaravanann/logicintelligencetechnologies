## 1. Executive Summary

This report evaluates the corporate platform's resistance against the OWASP Top 10 Web Application and API Security Risks. The platform implements multi-layered defensive controls, including strict Content Security Policies, cryptographic signature validation, fail-closed rate limiting, schema-enforced input parsing, and safe document handling.

## 2. HTTP Security Headers & Transport Hardening

All outbound HTTP responses generated by Next.js are augmented with hardened security headers configured in `next.config.ts`:

| Header Name | Configured Directive | Protection Vector |
| :--- | :--- | :--- |
| **Strict-Transport-Security (HSTS)** | `max-age=63072000; includeSubDomains; preload` | Enforces TLS 1.3 across all subdomains; eliminates SSL stripping. |
| **X-Frame-Options** | `DENY` | Completely prevents embedding in iframes; neutralizes Clickjacking. |
| **X-Content-Type-Options** | `nosniff` | Blocks MIME-type sniffing; forces browser adherence to declared Content-Type. |
| **Referrer-Policy** | `strict-origin-when-cross-origin` | Strips path data and credentials from Referer headers on cross-origin navigation. |
| **Permissions-Policy** | `camera=(), microphone=(), geolocation=(), browsing-topics=()` | Disables invasive browser APIs and ad-tracking FLoC/browsing topics. |
| **Content-Security-Policy (CSP)** | Restricts script, style, and object sources to `'self'` and trusted CDNs | Mitigates Stored, Reflected, and DOM-based Cross-Site Scripting (XSS). |

## 3. Injection Defenses & Input Sanitization

### A. Cross-Site Scripting (XSS)
1. **React JSX Architecture:** All dynamic data interpolated in React components is escaped automatically by the React rendering engine.
2. **Markdown Sanitization:** Dynamic content rendered from Markdown (e.g., technical blog articles, AI chatbot replies) passes through a sanitization pipeline using `dompurify` and `marked` with strict tag and attribute whitelisting (`<p>`, `<code>`, `<pre>`, `<ul>`, `<a>`). Script tags, inline event handlers (`onload`, `onerror`), and `javascript:` URIs are purged.
3. **SVG Vector Sandboxing:** In `next.config.ts`, SVG handling is configured with `dangerouslyAllowSVG: false` and strict sandbox directives:
   ```typescript
   contentSecurityPolicy: "default-src 'self'; script-src 'none'; sandbox;"
   ```

### B. SQL & NoSQL Injection
1. **Parameterized Queries:** Supabase PostgREST client utilizes prepared statements and parameterized queries for all database operations, eliminating SQL injection vectors.
2. **Direct SQL Avoidance:** Raw string concatenation in database queries is strictly forbidden across the codebase.

## 4. API Input Validation & Zod Schema Enforcement

Every API handler (`src/app/api/**/route.ts`) validates inbound request payloads against strict Zod schemas before processing:

```typescript
// Example: Contact Form Input Schema
export const contactFormSchema = z.object({
  fullName: z.string().min(2, "Name is required").max(100),
  email: z.string().email("Valid corporate email required").max(255),
  company: z.string().min(1, "Company name required").max(100),
  message: z.string().min(10, "Message must be at least 10 characters").max(2000),
  serviceInterest: z.enum(["ai_engineering", "cloud_architecture", "voice_shield", "advisory"]),
  honeypot: z.string().max(0).optional(), // Anti-bot honeypot field
});
```

- **Fail-Safe Error Responses:** Unprocessable entities trigger standard `400 Bad Request` responses containing mapped field error messages without leaking internal server details or database schemas.
- **Bot Mitigation:** Public contact and demo forms include hidden honeypot fields. Non-empty honeypot inputs immediately return synthetic success responses while dropping the payload.

## 5. Distributed Rate Limiting & Abuse Prevention

Rate limiting is governed by an Upstash Redis sliding window algorithm (`src/lib/ai/rate-limit.ts`) executed via atomic Redis Lua scripts:

### Quota Allocations by Surface

| Target Route / Surface | Allocated Window | Rate Quota | Action on Exceeded |
| :--- | :---: | :---: | :--- |
| `/api/chat` (AI Assistant) | 60 seconds | 20 requests | 429 Too Many Requests (with `Retry-After`) |
| `/api/contact` | 3600 seconds | 5 requests | 429 Too Many Requests |
| `/api/free-demo` | 3600 seconds | 5 requests | 429 Too Many Requests |
| `/api/automation/callback` | 60 seconds | 60 requests | 429 Too Many Requests |
| Public Static Pages | CDN / Edge | Uncapped | Cloudflare / Edge DDoS caching |

### Production Fail-Closed Guarantee
In `src/lib/ai/rate-limit.ts`:
- In local development mode, Redis unavailability allows requests with a console warning.
- In **production mode** (`NODE_ENV === "production"`), Redis connectivity errors cause the rate limiter to **fail closed**, returning HTTP 429 / 503 to shield downstream AI inference and database resources from denial-of-wallet exhaustion.

## 6. Safe PDF & Document Handling Architecture

The platform generates and serves corporate whitepapers, technical proposals, and contracts in PDF format (`src/lib/resources/pdf-resolver.ts` and `src/app/api/resources/[slug]/download/route.ts`):

1. **PDF Header Verification:** Pre-launch verification confirmed all 17 bundled corporate PDFs possess valid `%PDF-1.4` binary headers and correct file terminations (`%%EOF`).
2. **Slug Whitelisting:** Public download endpoints validate requested resource slugs against an explicit whitelist of registered technical whitepapers. Arbitrary file path traversals (`../../etc/passwd`) are rejected with `404 Not Found`.
3. **Middleware Crawl Protection:** `src/middleware.ts` intercepts requests targeting internal or private PDF storage paths, returning immediate `404 Not Found` responses to search engine bots and unauthorized scrapers.
4. **Content-Disposition Enforcement:** Served PDFs enforce `Content-Type: application/pdf` and `Content-Disposition: inline; filename="<sanitized-slug>.pdf"`.
